# 13 寸对话视口与输入框可见性修复

状态：执行中（代码与交叉测试已完成，等待内部包闭环）

日期：2026-08-01

## 1. 用户问题

Agent 工作区三栏方向已经正确，但 owner 在 13 寸 MacBook Pro 全屏实测发现：较长的
Agent 回复会把 Composer 推到窗口下方，只露出顶部边框，用户看不到输入框；同时当前
15px 消息正文在该密度下仍偏大。

## 2. 本轮范围

1. 消息正文从 15px 小幅降到 14px，不改变输入框和关键状态的可读性；
2. 约束 Agent 工作区的垂直网格，Transcript 只能在自己的区域滚动，不能撑高主窗口；
3. 在 1280×800 与 1440×900 两档加入长回复回归，硬性验证 Composer 全部位于视口内；
4. 复跑 Conversation、Agent 管理、Provider、Package 与产品旅程相关回归；
5. 交给 KimiCLI 独立检查完整 diff 和矮屏视觉门槛，修复到 CLEAN；
6. 更新进展、设计基线和测试用例，再生成唯一一份本地 unsigned internal 测试包。

## 3. 非目标

- 不改变三栏信息架构、Agent/会话关系或设置入口；
- 不新增多会话、Provider fallback、在线商店、价格/余额、P7/P8；
- 不发送真实消息，不读取 Provider Key，不请求 Provider，不消耗 credits；
- 不做 Apple Developer ID 签名、公证或在线发布。

## 4. 完成门槛

- 长回复使 Transcript 产生独立滚动时，Composer、Textarea 与发送按钮仍完整可见；
- 页面和工作区无纵向或横向逃逸，主区底部不超过浏览器视口；
- 1280×800、1440×900 截图和计算布局断言同时通过；
- 自主测试与 KimiCLI 均无 P0/P1/P2；
- clean commit 已推送，新包验收通过后才删除上一包，Downloads 与 dist 各只留一份。

- 高度链已改为“固定 Workspace/Main/Shell，只有 Transcript 收缩和滚动”；Gates 与
  Composer 均为不可收缩项；消息正文为 14px/1.68，Composer 输入保留 15px；
- 旧实现 1280×800 的 Renderer 高度为 768px，但 Composer Form 底部达到 884px；
  修复后 Form 底部分别为 750px（1280×800）和 823px（1440×900）；

  视口内；1180×760 既有视觉回归同样通过；
- Desktop syntax、142 项实际执行 Node 回归、Conversation/Agent 管理/Provider/Package
  Electron smoke、74 条产品旅程与 `git diff --check` 均通过；
- KimiCLI 独立复跑 syntax、两档长回复、Conversation 与产品旅程，最终结论 `CLEAN`，
  P0/P1/P2 均为 0；
