# Codex 风格 Composer 重设计计划

状态：实现与自动化完成；clean push 与唯一内部包待完成
日期：2026-08-04

## 背景

当前 Agent 对话 Composer 已经具备文字、附件、链接、听写、运行中调整、排队、立即执行、
停止、命令建议、历史和草稿恢复，但这些能力被拆成输入行、独立按钮行、说明 Footer 与状态
按钮组，视觉上更像复杂表单。用户提供的 Codex 输入框示例表明，主输入应该是一个安静、
完整、层级清楚的工作面板：上层只负责写内容，下层工具栏承载次要行动，右侧只保留一个
明确主操作。

本轮学习其信息层级和交互节奏，不复制 Codex 品牌、文案或不存在于 AgentMesh360 的控件。

## 目标

1. 把 Composer 收敛为单一大圆角容器，移除“输入框套输入框”的表单感；
2. 上层输入画布拥有足够留白，正文和 Placeholder 清晰但不夸张；
3. 下层工具栏左侧放附件与当前发送意图，右侧放听写、停止和发送；
4. 发送按钮改为清楚的箭头主操作，运行态停止改为同一操作区的方块按钮；
5. 保留准确隐私文案，但把它降为不打断输入的辅助说明；
6. 保留全部既有行为合同、选择器语义、键盘、ARIA、草稿、附件和 Queue authority；
7. 在 1180×760、1280×768、1280×800、1440×900 四档视口中完整可见。

## 产品结构

```text
单一 Composer 容器
├── 粘贴卡 / 附件 Chip（有内容时才出现）
├── 文字输入画布
├── 链接编辑 / 错误 / 建议浮层（按需出现）
├── 底部工具栏
│   ├── 左：添加附件 · 当前发送意图
│   └── 右：停止（运行时）· 听写 · 发送
└── 隐私或当前意图说明（辅助层级）
```

## 实施范围

- 调整 `desktop/src/ui/app.js` 的 Composer 语义结构和图标；
- 调整 `desktop/src/ui/style.css` 的容器、输入画布、工具栏、按钮、焦点和紧凑视口样式；
- 扩展 Electron/视觉/紧凑布局自动化，检查统一容器、图标主操作、可访问名称、字号、尺寸与
  四档视口；
- 增加结构化产品用例 `TC-CONV-027`，更新架构说明和项目进展；
- 在 clean push 后生成唯一未签名 arm64 内部包，完整复验后才删除旧包。

## 保留合同

- 文字与附件至少存在一个才允许发送；Enter 发送、Shift+Enter 换行、组合输入不误发；
- Agent 工作中仍可追加、排队、立即执行或停止，停止与 Queue mutation 相互独立；
- 附件、链接、命令、Skill、工作文件、历史、粘贴卡和本机听写能力不减少；
- 隐私文案精确保持：`附件仅在本机暂存，发送时交给当前模型；不会上传到 AgentMesh360`；
- 不在 Renderer 暴露 Session、路径、Provider Key、Core、Host 或 Bridge；
- 不把模型、推理强度、权限模式或不存在的 Goal/Custom 控件搬进 Composer。

## 验证计划

1. `node --check` 与 Desktop Node 全量；
2. Conversation Electron smoke，覆盖附件、听写、发送意图、停止、草稿和切 Agent；
3. 四档 compact smoke，验证 Composer、浮层和附件条不越界；
4. visual smoke，验证字体、容器宽度、主按钮与可访问名称；
5. 产品旅程验证器与 `git diff --check`；
6. clean pushed commit 冷构建 DMG/ZIP，验证 receipt、SHA、DMG、ZIP、包内 Host 与唯一包留存。

## 非目标

- 不增加 Provider、模型或付费依赖；
- 不改变 Harness、Queue、Cancel、附件存储和听写 authority；
- 不新增云附件库、音视频理解、多会话、P7/P8、签名、公证或在线发布；
- 不自动覆盖 `/Applications/AgentMesh360.app`。
