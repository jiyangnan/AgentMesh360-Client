# AgentMesh360 Client 界面设计基线

更新：2026-08-02

## 1. 目的

这份文档统一客户端页面的视觉语言和交互层级，避免每个模块单独定义字号、按钮、
卡片和弹窗。它不是一份已经完成全量迁移的声明：2026-07-31 起，Provider 管理页面
和持久 Agent 对话工作区已采用本基线，其他旧页面按产品计划逐模块迁移。

## 2. 产品界面原则

1. 默认页面先展示用户已经拥有和正在使用的对象。
2. 新增、编辑、删除确认进入下一层，不把长表单直接铺在管理列表前面。
3. 页面主行动只有一个；次要操作不能与主行动争夺视觉焦点。
4. 普通信息使用用户语言；协议、URL、模型 ID 等技术信息进入折叠详情。
5. 身份静默复验、窗口切换和普通导航不能清空用户草稿，也不能用全屏加载打断工作。
6. Agent 相关设置留在 Agent 管理；模型供应商页只维护供应商、Key 和可用模型。

## 3. 字体

- UI 字体：`--font-ui`
- 机器标识字体：`--font-code`
- 正文：`--text-body`，15px
- 对话消息正文：14px；Composer 输入仍使用 15px
- 小正文：`--text-small`，13px
- 辅助文字：`--text-caption`，12px
- 卡片标题：`--text-title`，20px

用户必须阅读或点击的文字不得使用 7–11px。等宽字体只用于 URL、模型 ID、版本、
Key 尾号等机器标识，不用于状态说明、按钮和普通中文文案。

## 4. 控件与间距

- 标准控件高度：`--control-height`，44px
- 表单输入建议高度：52px
- 控件圆角：`--radius-control`
- 卡片圆角：`--radius-card`
- 弹窗圆角：`--radius-modal`
- 间距统一使用 `--space-1` 至 `--space-8`

所有可交互控件必须有清晰的 `:focus-visible` 状态。危险操作使用应用内确认弹窗，
不使用系统原生 `window.confirm` 承担对象删除。

下拉选择统一使用应用内 `role="combobox"` 触发器与 portaled `role="listbox"` 菜单，
不得调用 macOS 原生弹出菜单。菜单视觉使用同一字体、颜色、圆角、阴影和焦点态；支持
鼠标、方向键、Home/End、Enter/Space、Escape、Tab、点击外部关闭、选项分组、禁用态、
长列表滚动和视口上下翻转。隐藏的原生 `select` 只保留表单值和既有 `change` 合同。

## 5. 管理页层级

标准管理页由以下层级组成：

1. 页面标题与一句职责说明；
2. 列表工具栏：列表标题、对象数量说明、唯一主行动；
3. 已配置对象列表或带行动入口的空状态；
4. 每行的公开状态和常用操作；
5. 默认折叠的技术详情与诊断；
6. 页面底部的安全或数据归属说明。

新增和编辑使用同一个模态窗口。关闭窗口保留草稿；“放弃更改”才清空草稿。保存成功
后关闭窗口并刷新列表；保存失败保留字段并给出可恢复错误。

## 6. Provider 页面当前合同

- 默认显示“已配置的模型供应商”列表，不显示配置表单。
- “配置新供应商”和“编辑”打开同一个配置弹窗。
- 列表名称不小于 16px，状态和元信息不小于 13px，操作文字不小于 13px。
- 协议、接口地址和三档检查位于“连接详情与诊断”折叠区。
- 删除使用应用内影响确认弹窗，并列出受影响 Agent。
- Provider 草稿跨普通导航和身份静默复验保留，换账号时清空。
- Key 不进入页面 HTML、日志、测试证据或公开状态。

## 7. 测试门槛

每个迁移到本基线的管理页至少覆盖：

- 零、一个和多个对象的默认列表状态；
- 默认无编辑器，真实点击后才出现 `role="dialog"`；
- 键盘 Escape、焦点进入和关闭后的焦点恢复；
- 暂时关闭保留草稿，明确放弃清空草稿，换账号隔离；
- 真实按钮完成保存、更新和删除，列表同步变化；
- 失败时不显示假成功且保留可恢复输入；
- 关键字号、字体族、控件高度和折叠层级的计算样式断言；
- 1180×760 的列表和弹窗视觉快照。

## 8. Agent 首页引导当前合同

- 首页引导卡是纯提示，不承担跳转；卡内不得出现按钮、链接、hover 行动暗示或动态
  “下一步”标题。
- 唯一主内容是“添加模型供应商 → 激活 Agent → 在 Agent 对话中开始工作”三步有序列表；
  DOM 使用 `ol > li`，不能退化为依靠全角空格拼接的一行文字。
- 三个步骤使用同一主要视觉层级，步骤文字不小于 13px；数字与连接线只负责表达先后关系，
  不伪装为进度完成态。
- Provider/Agent 异步状态不得替换或闪烁提示文案；真实行动入口保留在左侧导航和 Agent
  卡片。
- 1180×760、1280×800 与宽屏均须无横向溢出；安装验收必须确认顺序、无误导文案和
  卡内交互元素为 0。

## 9. Agent 对话工作区当前合同

- 三栏只在已激活 Agent 工作区出现：全局导航、Agent/会话二级栏、主内容。
- 二级栏上半区列真正常驻 Agent；下半区只列 Host 返回权威支持的会话。当前只有一条
  “主会话”，不得用本地目录扫描伪造更多会话。
- 打开 Agent 默认直接进入对话；模型、行为和用户偏好只从右上角齿轮进入设置。
- 对话工具栏保持紧凑，只显示 Agent 身份、主会话状态和 44×44px 设置齿轮。
- 消息与 Composer 使用居中阅读列，宽度不超过 900px；消息正文为 14px，Composer 输入
  为 15px，发送者、状态和关键说明不小于 12px。
- Composer 固定在主内容底部且不得参与收缩，Transcript 独立滚动；长回复、权限提示和
  错误提示只能压缩 Transcript，不能把输入框推到视口外；输入框不允许被拖成半屏。
- Composer 左侧只提供一个 40×40px 的“＋”入口；应用内浮层只显示“图片或文件”和
  “网页链接”两个用户动作，不把 ACP Block、协议或 Provider 技术选项暴露给普通用户。
- 选中的图片、文件和链接统一显示为单行附件 Chip；最多 10 个，超过阅读列宽度时只横向
  滚动，附件条高度必须小于 55px，不能通过不断增高 Composer 挤压 Transcript。
- 支持系统文件选择、Finder 拖放以及粘贴截图；允许只发送附件。发送按钮只有在文字或附件
  至少存在一个时启用，失败时保留文字和附件，成功后清理本条附件。
- Renderer 只显示附件名称、类型、大小和安全化链接摘要，不接收本机路径、文件字节或
  Base64；输入区必须明确说明内容不上传 AgentMesh360 Core，但会交给所选 BYOK 模型处理。
- 模型文本先转义，再只处理段落、粗体、列表和行内代码；模型原始 HTML、事件属性和
  Script 不进入 DOM。
- 对话草稿至少按账户、Agent 和公开会话键隔离；Agent 设置草稿按账户、Agent 和设置类型
  隔离。任何重渲染只能从表单自身的归属字段捕获草稿，不能依赖已切换的全局 Agent 状态。
- Agent 的 busy/streaming 状态只属于它自己；侧栏不得因为 A 初始化或生成而禁用 B/C。
  A 继续在后台运行，迟到状态只能更新 A 的状态标记，不能替换当前会话内容。
- 1180×760、1280×800 和 1440×900 都必须无横向或纵向逃逸；1280×800 与 1440×900
  使用超过 Transcript 高度的真实长回复 fixture，并计算验证 Composer、Textarea 和发送
  按钮全部位于视口内；真实安装验收不得发送消息或触发 Provider 请求。

## 10. 后续迁移边界

现有 Package 和设置等页面仍有历史小字号和硬编码样式。当前已修正 Provider、Agent 首页
三步提示、持久 Agent 对话工作区及全局基础 token，不借机重写 Package 或设置页面。真正多会话必须
先补 Host Registry、账户边界和公开会话接口，不能只在 Renderer 增加按钮。后续必须按
既定产品计划逐模块迁移，并在每轮进展文档中记录已迁移范围和剩余债务。
